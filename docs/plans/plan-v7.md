# plan-v7 — 세션 recap도 backlog doc으로 기록, /clear 정책 명확화

이전 버전: plan-v1~v6.md (모두 변경하지 않음)

## 변경 사항(불변식에 추가)

### 1. recap 기록
오케스트레이터 세션이 사용자에게 주는 진행 상황 recap/요약 메시지도 채팅에만 남기지 않고
`backlog doc`(`진행 로그`, doc-3)에 시간순으로 누적 기록한다. `backlog doc update doc-3
--content "..."`로 기존 내용에 이어붙인다.

### 2. "/clear 후 다음 태스크" 정책
- Claude Code는 `/clear`를 세션이 스스로 호출할 수 있는 도구를 제공하지 않는다(사용자가
  치는 슬래시 커맨드) — 오케스트레이터 세션이 자신을 지우면 계획/불변식/리뷰-검증 조율 맥락이
  함께 사라진다.
- 대신 **leaf task 구현은 항상 서브에이전트(완전히 새 컨텍스트)에 위임**하는 기존 불변식이
  "태스크 하나 끝나면 컨텍스트를 비우고 다음 태스크로" 요구를 구조적으로 만족시킨다 — 서브에이전트
  = 매번 clear된 상태로 시작. 오케스트레이터 세션 자체는 조율 역할이라 계속 유지한다.
- 프롬프트 캐싱은 세션/서브에이전트 각각 인프라 차원에서 자동 적용되며, 별도 설정은 하지 않는다.
  서브에이전트 프롬프트의 반복 구간(계획 요약 등)은 표현을 최대한 동일하게 유지해 캐시 적중률을
  높인다.
