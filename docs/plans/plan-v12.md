# plan-v12 — 상태를 인용할 땐 브랜치/ref가 아니라 커밋 전체 해시로

이전 버전: plan-v1~v11.md (모두 변경하지 않음)

## 문제

reviewer/verify/logger/구현 세션들이 서로 "origin/main 기준으로 확인", "이 브랜치 기준으로
검증" 처럼 **브랜치명(ref)**으로 상태를 인용하는 경우가 많았다. 브랜치는 계속 움직이는
포인터라, 같은 브랜치명이라도 시점에 따라 가리키는 커밋이 달라진다. 실제로 이번에 milestone
태그 수정 커밋이 "이미 머지된 PR 브랜치에 추가로 push"되어 main에는 전혀 반영 안 된 채로
방치된 사고가 있었는데, 이런 상황에서 "그 브랜치 기준으로 확인했다"는 기록만으로는 정확히
어느 커밋을 봤는지 사후에 재구성하기 어렵다.

## 규칙(반드시 지켜야 함, 모든 세션 공통)

어떤 상태(리뷰 결과, 검증 결과, "이 시점에 이랬다" 같은 기록)를 backlog doc/task notes에
남길 때는 브랜치명만 쓰지 않고 **반드시 그 시점의 전체 커밋 해시(`git rev-parse HEAD`
또는 `git log -1 --format=%H`, 짧은 해시가 아니라 전체 40자)를 함께 기록**한다.

예:
- 나쁜 예: "origin/docs/plan-v9-TASK-9 브랜치 기준으로 확인함"
- 좋은 예: "origin/docs/plan-v9-TASK-9 브랜치, 커밋 c2e129d... (전체 해시) 기준으로 확인함"

PR 링크나 머지 커밋도 마찬가지 — "PR #7 머지됨"뿐 아니라 머지 커밋의 전체 해시까지 남긴다.
**또한 이미 머지된 PR 브랜치에 나중에 커밋을 추가로 push해도 main에 자동 반영되지 않는다** —
반드시 새 PR을 열어야 한다(이번 사고의 직접 원인).

## 영향받는 범위
- reviewer, verify, logger 세션에 공지
- 클라우드 크론 프롬프트에도 반영 필요
